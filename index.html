This is an ER-style notation

      
ER diagrams model any kind of system, before anyone has decided how it will be stored. That is why ER has 1‑1, 1‑N and N‑N relationships.

      
A SQL database is more concrete. It has tables with columns, and a foreign key is a column that points to a column in another table. Between two tables that is always 1‑N: many rows can hold the same key, and each of them points to exactly one row.

      
    
        
  • N‑N doesn't exist between two tables. It is always built as a junction table with two foreign keys.
    • 
        
  • 1‑1 is usually just columns in the same table, or a foreign key marked unique (drawn here as 1‑1).
    • 
      

      
Why it's everywhere: ER notation comes from 1970s design methods: Chen's ER model, and crow's feet from Information Engineering. The database design tools of the 80s and 90s kept those symbols when they started drawing real tables, and still call the result an "ER diagram". Textbooks and tutorials copied them, so that is what a web search shows.

      
The arrows show exactly which column points to which, and that is what you need to write a JOIN. ER symbols only tell you that two tables are related.
